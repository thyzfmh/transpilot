# 自治源码迁移通用方法

## 1. 目标

把已有项目迁移到新的语言或实现，不以“生成了代码”或“目标项目测试通过”为完成标准，而以源项目可观察行为、公开契约和独立验证均可复现为完成标准。

该方法不绑定具体项目、语言、构建系统或测试框架。每个任务通过项目适配器提供路径和命令，语言对参考文件提供 ABI、类型和运行时约束。

## 2. 三层结构

1. 通用方法：发现、建立事实源、形成工作队列、持续验证、断点恢复和最终取证。
2. 语言对约束：例如 C 到 Rust 的 ABI、整数、指针、错误、回调和内存安全规则。
3. 项目适配器：源/目标路径、构建命令、测试入口、产物位置和特定配置。

通用方法不得写入项目测试名称、固定用例数量、业务模块名称或结构体字段。测试与模块必须由发现程序形成；只有无法从仓库机械推导的路径、命令、产物和语言边界映射才由项目适配器提供。

## 3. 事实优先级

按以下顺序解决冲突：

1. 源实现的可重复运行结果。
2. 源项目原生测试和断言。
3. 公开接口、数据格式、构建配置和源码分支。
4. 源项目文档和注释。
5. 目标实现及其自有测试。

目标实现不能反向定义预期值。目标语言测试主要用于缩短调试反馈，不是兼容性证明。

## 4. 发现阶段

机械生成项目画像，包括：

- 语言和文件分布；
- 构建系统和可执行命令；
- 原生测试入口、测试标识和执行顺序；
- 公开接口和目标产物；
- ABI、数据格式、协议、存储或进程边界；
- 运行依赖和固定配置。

先运行未修改的源项目测试，确认基线可用。无法运行完整测试时，为当前行为写最小源端探针并保存命令和输出。

对机械发现的每个原生测试套件，从等价清理状态分别运行源实现和目标实现。源实现至少重复两次，用重复结果识别非确定数据；目标实现必须保持相同的测试用例结果、相对副作用路径、创建/修改/删除集合、文件尺寸，以及源实现各次运行均稳定的内容字节。这样由原测试自然覆盖的更新、删除、回收、跨区、重开和遍历行为都会进入差分，而通用方法无需知道业务 API 或固定操作序列。

公开接口闭合与行为覆盖必须分开记录：所有接口都通过自动生成的编译、链接、ABI 或常量值探针；原测试实际调用的接口再由源/目标差分验证行为。原测试未调用的接口只能标记为 ABI-only，不能靠通用 Skill 猜测业务输入，也不能伪称行为已验证。

## 5. 最早真实反馈

迁移开始后优先打通以下链路：

```text
源测试或源调用方 -> 目标产物 -> 真实运行结果
```

尽早暴露缺失符号、调用约定、布局、生命周期和错误码问题。禁止先花大量时间编写目标语言自测、报告或覆盖表，最后才连接真实调用方。

## 6. 工作单元

工作队列从项目事实动态产生，可由以下项目组成：

- 原生测试用例；
- 公开 API；
- 源模块和关键状态机；
- ABI 或数据格式契约；
- 原测试未覆盖但公开可观察的边界。

每个工作单元必须经历：读取完整事实源、观察失败、最小实现、聚焦验证、源原生回归、记录下一项。一次只保留一个首要失败。

实现前为当前工作单元形成简短契约表：输入与边界、输出与错误、状态转换、外部副作用、持久化字节、回调和资源释放。表中每个预期必须指向源测试、源代码公式或可复现的源端探针。目标实现及其输出不能成为预期来源。

迁移顺序优先采用自底向上：常量和类型语义、字节格式与底层 I/O、状态机、公开边界。目标语言聚焦测试应在修复前从源测试或源端探针转写；完成后仍必须回到原调用方验收。

## 7. 验证节奏

采用分层门禁：

1. 聚焦门禁：当前失败行为。
2. 源原生门禁：源测试针对目标产物。
3. 目标内部门禁：目标语言测试、格式和静态检查。
4. 契约门禁：ABI、接口、持久化、协议、安全或性能要求。
5. 最终门禁：干净状态下重复执行全部必要验证。

行为未通过时只运行能提供信息的门禁。报告、证据索引和审计汇总推迟到行为稳定之后。

## 8. 断点恢复

把执行状态写入机器可读文件，至少包含：

- 当前阶段和工作单元；
- 最近命令及退出码；
- 当前通过、失败、未运行数量；
- 首个失败；
- 下一条明确命令；
- 源和目标版本哈希。

上下文压缩或进程续跑后，先读取状态并执行下一条命令，不重新从头分析。状态文件只记录事实，不记录长篇推理。

## 9. 防止无效循环

同一方法连续失败三次后必须改变方法。可选动作包括缩小切片、增加源探针、检查更低层调用、验证布局、替换数据模型或架构。重复读取和重复描述同一问题不算进展。

单条命令应有合理超时，完整日志写文件，终端只输出用例计数、首个失败和关键错误，避免大量输出消耗上下文。

## 10. 完成标准

只有同时满足以下条件才能完成：

- 所有发现到的源原生测试都针对目标产物通过；
- 适用的公开契约门禁通过；
- 无占位实现或被削弱的验证；
- 源输入和固定验证器未被修改；
- 从干净状态重复验证通过；
- 当前执行的交互记录和机器验证产物完整导出。

测试数量和模块名必须由仓库机械发现；产物位置和无法推导的构建入口属于项目适配器，不属于本方法。
