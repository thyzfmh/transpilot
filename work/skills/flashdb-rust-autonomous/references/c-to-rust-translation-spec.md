# C 到 Rust 通用迁移约束

本规范约束 C 项目迁移到 Rust 时的语言边界。项目路径、测试名称、固定配置和产物位置必须由项目适配器提供。

## BASE-01 源实现是语义基准

- 必须阅读 C 调用链、条件编译、宏、错误分支和原生测试。
- C 行为不明确时，必须运行原实现或建立最小 C 探针。
- 禁止从当前 Rust 输出反推预期值。

## PROF-01 配置画像必须明确

- 必须记录并验证参与编译的宏、类型宽度、后端和功能开关。
- 只能声明实际构建和验证过的配置。
- 配置变化必须使旧布局和旧行为证据失效。

## IMM-01 源输入和验证器不可修改

- C 源码、头文件、测试和构建入口必须由不可变清单保护。
- 固定 harness 不得被目标实现替换、删除或放宽。

## COV-01 工作队列必须由源码发现

- 必须机械发现原生测试、源模块和公开接口。
- 固定测试数量、模块名和业务名称不得写入通用循环。
- 每个发现项必须有通过、失败或未运行状态。

## API-01 公开 API 必须逐项闭合

- 必须从公开头文件提取函数、常量、控制命令和回调类型。
- 每个函数必须由自动生成的 C 地址引用完成编译、目标产物链接和 LLVM ABI 签名比对；每个常量必须编译 C/Rust 两端并比较实际值。
- 原测试存在调用点的接口必须进入源/目标行为差分；没有原调用点的接口必须明确标记为 ABI-only，不得伪称已经验证行为。
- 原调用方覆盖必须来自可编译调用点或运行覆盖，不得以注释、声明或普通文本命中代替。
- 禁止以空实现、固定成功或默认值满足链接。

## TDD-01 必须采用源测试优先

- 主要验收必须让原 C 测试或原 C 调用方直接运行 Rust 产物。
- 最终验证必须先清理并重建原 C 实现，证明源基线中的所有机械发现用例自身通过。
- 应尽早建立该链路，先解决编译、链接、ABI 和首个行为失败。
- Rust 测试可用于聚焦调试，但不得替代源原生验收。
- 聚焦 Rust 测试必须在修复前从原 C 用例或源端探针转写，保留输入、执行顺序、断言和边界；禁止根据当前 Rust 实现编写能通过的预期。
- 预期值只能来自 C 测试、C 源码、C 运行轨迹或机械公式。
- 每次构建只登记一个待测产物，源测试、差分测试和契约探针必须复用同一产物。

## INT-01 整数和位运算语义必须等价

- 必须核对宽度、符号、整数提升、截断、溢出、移位和按位取反。
- 宏和控制命令不能只比较名称，必须编译 C 与 Rust 两端并比较实际数值。
- 持久化字段使用固定宽度类型，转换为 `usize` 前检查边界。
- 对齐和长度必须使用与 C 宏等价的公式。

## LAY-01 布局必须测量

- C ABI 结构必须使用 `#[repr(C)]` 并由 C/Rust 探针比较大小、对齐和字段偏移。
- 持久化格式必须作为字节协议实现，不能直接序列化普通 Rust 结构体。
- 禁止根据平台习惯或人工计算猜测偏移。

## STA-01 状态机必须保留

- 必须保留合法状态、转换顺序、恢复路径、删除、回收和遍历顺序。
- 不能用只保留最终业务值的高层集合替代可观察状态机。
- 必须覆盖空、满、跨区域、重复写、重启和损坏边界。
- 实现前必须列出当前工作单元的前置状态、输入、成功状态、每个错误出口和介质副作用，逐分支对照 C 调用链。

## PST-01 持久化必须独立恢复

- 进程内缓存不能成为唯一事实源。
- 关闭重开后必须从介质恢复状态。
- 读写、擦除、空间和校验错误必须沿调用链返回。

## XIO-01 必须验证双向兼容

- 必须让机械发现的同一批源调用方分别运行原实现和 Rust 产物。
- 两次运行必须从等价清理状态开始，并比较用例顺序、退出状态和全部文件副作用。
- 原测试覆盖到的更新、删除、容量边界、恢复和遍历行为必须自动进入差分，不得在通用 Skill 中手写业务 API 或固定操作数量。
- 源实现必须重复运行以校准非确定数据；文件副作用应比较相对路径、创建/修改/删除状态、长度，以及各次源运行均稳定的内容字节，而不只比较业务返回值或要求动态字节哈希偶然相同。

## ABI-01 C ABI 必须精确

- 导出名、参数、返回值和调用约定必须与头文件一致。
- 指针空值、长度、别名、生命周期和可写性必须在边界处理。
- Rust panic 不得跨越 FFI 边界。
- 不得跨语言混用不匹配的分配和释放方式。

## MEM-01 默认使用安全 Rust

- 所有权数据使用安全容器，借用数据使用切片，可空值使用 `Option`，错误使用 `Result`。
- `unsafe` 仅用于不可避免的 FFI 或底层边界，并缩小到最小范围。
- 禁止生产代码中的 `static mut`、`unwrap`、`expect`、`panic` 和未完成宏。

## ERR-01 错误和输出参数必须等价

- 必须保留不同错误码，不得吞错或统一成成功。
- 失败时输出参数是否修改必须以 C 行为为准。
- 空数据、未找到和错误必须保持区别。

## CBK-01 回调契约必须保留

- 必须保持调用次数、顺序、停止条件、上下文和返回值影响。
- 调用外部回调时不得持有会造成重入死锁的内部锁。
- 回调和上下文的保存时间不得超过 C 生命周期保证。

## GLB-01 全局状态边界必须明确

- 必须区分库级、实例级和测试级状态。
- 多实例、重复初始化、反初始化和重入必须互不污染。
- `Send` 或 `Sync` 必须有真实同步和生命周期依据。

## EVD-01 证据必须自动绑定当前实现

- 源原生测试结果必须由固定运行器生成并记录源、目标和日志哈希。
- 修改目标构建输入后，旧的最终证据必须失效。
- 禁止手写通过状态或把自然语言结论当作证据。

## LOG-01 交互和验证日志必须完整

- 必须导出当前执行的完整交互记录，不得删改。
- 必须同步保存构建、源原生测试、互操作、接口和安全门禁日志。
- 会话中的“完成”不能替代代码级验证。

## VER-01 完成必须独立验证

- 所有机械发现的源原生测试必须针对 Rust 产物通过。
- 适用的 ABI、公开接口、持久化、互操作和安全门禁必须通过。
- 必须在干净状态下重复最终验证，并确认没有占位实现。
